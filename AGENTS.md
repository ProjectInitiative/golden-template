# Agent Working Guide — Golden Template

This document defines the standard operating model for AI agents working across ProjectInitiative repositories. It is a meta-guide: agents should read this first, then consult the per-project `AGENTS.md` and `devenv.nix` for project-specific instructions.

## Agent Workflow: Using This Repo

When creating a new project or converting an existing one to Nix:

1. **Identify the project type** from the table below (Python, Rust, Go, Node, Embedded, Container, Dev Shell, Nix Library, NixOS Config, or Wrapper Project).
2. **Scaffold via `nix flake init -t`** — this is the canonical entry point:
   ```bash
   nix flake init -t github:projectinitiative/golden-template#python
   ```
   This generates all the standard files (`flake.nix`, `devenv.nix`, `.envrc`, `AGENTS.md`, `treefmt.toml`, CI pipeline) plus stub source code.
   Available templates: `python`, `rust`, `go`, `node`, `embedded`, `compiled-serverless`, `container`, `dev-shell`, `nix-library`, `nixos-config`, `wrapper`.
3. **Customize** the generated files: update `pname`, `version`, `dependencies`, and project-specific logic. The template's `AGENTS.md` gives you per-type commands and workflows.
4. **Iterate** using `devenv shell -- <command>` for fast feedback (e.g., `devenv shell -- cargo build`, `devenv shell -- uv run pytest`, `devenv shell -- go test`).
5. **Use services** with `devenv up` to start databases, caches, and background processes.
6. **Validate** with `nix flake check && nix build` before submitting.
7. **Consult extensions** when the template doesn't cover your exact case:
   - `docs/project-type-reference.md` for the full pattern reference
   - `docs/ci-strategies.md` for CI setup options
   - Per-template files in `templates/<type>/` for the complete source
   - `PROJECT_MIGRATION_GUIDE.md` for migrating existing projects to devenv

This repo is designed as both a scaffolding tool AND a living reference — agents should use the template generator as the starting point, then consult the documentation for deeper patterns.

## Core Principles

1. **Nix-first** — Every project must have a `flake.nix` that provides a reproducible build and development environment.
2. **Devenv-powered** — Development environments use `devenv` for language tooling, services, and process management.
3. **DRY dependencies** — `devShells` must inherit from the main package derivation whenever a package target exists. Never duplicate dependency lists.
4. **Structured outputs** — Every flake must define `packages.default`, `devShells.default`, `checks`, and `formatter`.
5. **Hermetic builds** — No network access during sandboxed builds (`nix build`). Use `devenv shell -- <build cmd>` for iterative local work.
6. **CI parity** — CI must run `nix flake check` (formatting + tests) and `nix build`.

## Standard File Layout

```
project-root/
├── flake.nix              # Entry point — flake-parts + devenv.flakeModule
├── devenv.nix             # Declarative dev environment (languages, services, processes)
├── flake.lock             # Pinned inputs (auto-generated by `nix flake update`)
├── .envrc                 # `use flake` — enables direnv automatic shell loading
├── AGENTS.md              # Agent working guide (project-specific)
├── DESIGN.md              # Architecture decisions and rationale
├── treefmt.toml           # Formatter configuration (clang-format, nixfmt, prettier, etc.)
├── package.nix            # (optional) Standalone derivation for non-flake consumption
├── .github/workflows/     # CI pipelines
│   └── ci.yml             # Standard CI: check + build
├── nix/                   # (optional) Supporting Nix files (scripts, overlays, modules)
├── src/ or main/          # Source code
├── tests/                 # Tests
└── docs/                  # Documentation
```

## Common Flake Pattern

Every project flake should follow this skeleton:

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    flake-parts.url = "github:hercules-ci/flake-parts";
    flake-parts.inputs.nixpkgs-lib.follows = "nixpkgs";
    devenv.url = "github:cachix/devenv";
    devenv.inputs.nixpkgs.follows = "nixpkgs";
    # project-specific inputs (crane, uv2nix, esp-dev, etc.)
  };

  nixConfig = {
    extra-trusted-public-keys = "devenv.cachix.org-1:w1cLUi8dv3hnoSPGAuibQv+f9TZLr6cv/Hm9XgU50cw=";
    extra-substituters = "https://devenv.cachix.org";
  };

  outputs = inputs@{ flake-parts, ... }:
    flake-parts.lib.mkFlake { inherit inputs; } {
      imports = [ inputs.devenv.flakeModule ];
      systems = [ "x86_64-linux" "aarch64-linux" "x86_64-darwin" "aarch64-darwin" ];

      perSystem = { config, pkgs, ... }: {
        packages.default = # ... project derivation ...

        devenv.shells.default = {
          imports = [ ./devenv.nix ];
          packages = [ config.packages.default ];
        };

        checks = {
          formatting = # ... treefmt check ...
          tests = self'.packages.default;
        };

        formatter = pkgs.nixfmt;
      };
    };
}
```

## Common Devenv Pattern

Every project's `devenv.nix` should follow this structure:

```nix
{ pkgs, config, ... }: {
  # Language tooling
  languages.python.enable = true;   # or: go, rust, javascript, etc.

  # Services (start with `devenv up`)
  services.postgres.enable = true;
  services.redis.enable = true;

  # Background processes
  processes.api.exec = "npm run dev";

  # Shell entry message
  enterShell = ''
    echo "Project dev environment"
  '';

  # Pre-commit hooks
  git-hooks.hooks.nixfmt-rfc-style.enable = true;

  # Test command
  enterTest = ''
    go test ./...
  '';
}
```

## Mandatory Pre-Submission Check

Before requesting review or submitting, you **MUST** run:

```bash
nix develop --command agent-check   # or equivalent: ci-ready, pre-submit, etc.
```

This enforces:

1. Clean working tree (all changes committed)
2. Formatting compliance (`treefmt --fail-on-change`)
3. Unit tests passing
4. Build succeeds (`nix build`)
5. No merge conflicts (if applicable)

## Project Type Reference

See `docs/project-type-reference.md` for detailed patterns. Quick summary:

| Type                | Input                                                | Builder                                                         |
| ------------------- | ---------------------------------------------------- | --------------------------------------------------------------- |
| Python (uv2nix)     | `uv2nix`, `pyproject.nix`                            | `pythonSet.mkVirtualEnv`                                        |
| Rust (crane)        | `crane`                                              | `craneLib.buildPackage` (split deps/src)                        |
| Go                  | (built-in)                                           | `buildGoModule`                                                 |
| Node/JS             | (built-in)                                           | `buildNpmPackage`                                               |
| Embedded            | `esp-dev`, `arduino-nix`                             | `stdenv.mkDerivation` + toolchain                               |
| Compiled Serverless | `ops-utils`                                          | `buildGoModule` / `craneLib.buildPackage`                       |
| Ingestion Pipeline  | `uv2nix`, `pyproject.nix`, `pyproject-build-systems` | `pythonSet.mkVirtualEnv` + NATS JetStream + Fission MQ triggers |
| Container           | (built-in)                                           | `dockerTools.buildImage` / `streamLayeredImage`                 |
| Dev shell only      | (none needed)                                        | `mkShell`                                                       |
| Nix library         | (none needed)                                        | `lib` output set                                                |
| NixOS config        | (various)                                            | `nixosSystem`                                                   |
| Wrapper project     | `upstream-src` (flake=false)                         | `stdenv.mkDerivation` + `.direnv/vendor/`                       |

## Template Scaffolding

To bootstrap a new project from a template:

```bash
# From this repo
nix flake init -t .#python        # or: rust, go, node, embedded, container, etc.

# From GitHub
nix flake init -t github:projectinitiative/golden-template#python
```

If the template does not cover your exact needs:

1. Start from the closest template
2. Consult `docs/project-type-reference.md` for the full pattern
3. See `PROJECT_MIGRATION_GUIDE.md` for adapting the pattern
4. Run `nix flake check && nix build` to verify

## Self-Validation (This Repo)

This repository validates itself to ensure all templates remain correct:

```bash
# Quick check (formatting + eval)
nix flake check

# Full template validation
nix develop --command validate-templates

# Pre-submission (everything)
nix develop --command agent-check
```

The `validate-templates` script:

1. For each template, creates a temp directory
2. Copies template files into the temp dir
3. Runs `nix flake check` (validates eval + formatting)
4. Runs `nix build` (for templates that support it)
5. Reports pass/fail for each template
