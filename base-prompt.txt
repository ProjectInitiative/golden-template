You are converting an existing Nix project to the golden-template architecture (devenv + flake-parts). Follow this guide:

## Phase 1: Flake restructure

1. Replace `flake-utils` with `flake-parts` + `devenv.flakeModule`
2. Add `nix2container` input (required by devenv internally even if not using containers)
3. Add `nixConfig` for devenv.cachix.org
4. Support 4 systems: x86_64-linux, aarch64-linux, x86_64-darwin, aarch64-darwin
5. Move dev shell from `mkShell` to `devenv.shells.default`

## Phase 2: Create devenv.nix (Phase 3 pattern - everything in one file)

`devenv.nix` is the SINGLE source of truth. Use `outputs.<name>` for build artifacts:

```nix
{ pkgs, config, ... }: {
  # Disable cache management if system handles it
  cachix.enable = false;

  # Language tooling
  languages.X.enable = true;

  # Dev-only tools (not needed for build)
  packages = with pkgs; [ tool1 tool2 ];

  # Build environment vars (needed by sys crates)
  env.PKG_CONFIG_PATH = "...";
  env.LIBCLANG_PATH = "...";

  # The build itself
  outputs.app = pkgs.XXX.buildXXXPackage {
    pname = "my-app";
    # ... build config
  };
}
```

`flake.nix` just extracts:
```nix
packages.default = config.devenv.shells.default.outputs.app;
```

## Phase 3: Register inputs

After adding language/hook config, run:
```bash
devenv inputs add rust-overlay github:oxalica/rust-overlay --follows nixpkgs
devenv inputs add git-hooks github:cachix/git-hooks.nix --follows nixpkgs
```

## Common pitfalls to check

- [ ] `inputsFrom` doesn't propagate env vars - set them explicitly in `env.`
- [ ] Set `PKG_CONFIG_PATH` and `LIBCLANG_PATH` in BOTH build and `devenv.nix env`
- [ ] Add `nix2container` input to `flake.nix` (devenv requires it internally)
- [ ] `cachix.enable = false` if user has system nix cache config
- [ ] User needs `devenv` 2.x and `use_devenv` direnv function for clean runtime
- [ ] Gitignore `.pre-commit-config.yaml` (auto-generated by devenv)
- [ ] Handle both `sha256:<base32>` AND `sha256-<base64>` hash formats if parsing narHash
